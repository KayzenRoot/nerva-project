# M04 Agent Wallet, Permissions and Verifiable Evidence

## Authority and safety boundary

M04 stores public wallet/account identity and verifiable authorization references. NERVA never receives or stores a wallet private key, seed phrase or mnemonic. It has no transaction signer, wallet delegation writer, arbitrary call, calldata, contract target or selector interface. `MAINNET` effectful execution is hard-blocked and live Perpl writes remain blocked. A wallet signature only proves approval of the exact typed authorization; it does not prove policy safety, simulation, provider enrollment or permission to dispatch an effect. M03 remains the only planning/simulation/kill-switch/idempotency/recovery boundary, and its effect port remains closed.

Only `REDUCE_POSITION`, `CLOSE_POSITION` and `NO_ACTION` are representable. Grants are strict and bound to Monad Testnet chain ID `10143`, account, wallet, versioned agent, M03 policy digest, position/market scope, quantitative bounds, expiry, revocation generation and nonce domain. There are no wildcards. Natural language and LLM output are untrusted suggestions and never grant authority. `LIQUIDATION_DISTANCE`, `MAINTENANCE_MARGIN` and `FUNDING_DIRECTION` remain `UNAVAILABLE_UNPROVEN`/non-authoritative.

## Wallet binding and authorization flow

The owner starts a wallet-bind, grant, plan authorization, grant/session revocation or unbind request without a signature. The API returns the exact EIP-712 typed-data challenge and domain. The user reviews and signs through their external wallet. The second request carries the signature; NERVA verifies the exact typed-data structure and recovers the expected public signer before persisting a proof reference and consuming a durable nonce. The application stores only a digest/reference to the proof, never a reusable raw wallet signature. Wallet and agent endpoints reject unknown properties and chain/account mismatches.

Private account permission read models require a separate, short-lived EIP-712 read authorization bound to the exact account, wallet and testnet chain. The API's challenge endpoint returns no permission records; a successful signature must match the currently bound wallet and its unique durable read nonce is consumed before the account-scoped response is returned. The dashboard requests this proof through an EIP-1193 injected wallet and `eth_signTypedData_v4`; it never requests a transaction. The global evidence integrity endpoint exposes only integrity/count/hash metadata.

The API shape is compatible with EIP-712-capable wallets. MetaMask Agent Wallet's official guide documents the `mm wallet sign-typed-data --chain-id ... --payload ...` operation, and the current supported-chain page lists Monad Testnet (10143). The CLI's version-specific `mm chains list` output is documented as authoritative. The present environment did not have `mm` installed, so no CLI signing session or wallet/provider integration was exercised. NERVA does not claim MetaMask Agent Wallet identity, Transaction Shield coverage on Monad Testnet, or a tested Agent Wallet integration. The current feature uses the generic EIP-712-compatible external signer boundary only. No raw transaction command is called.

## Delegation observation

The read-only observer checks `eth_chainId`, a finalized block, and the wallet's bytecode at that block hash. It parses only the EIP-7702 `0xef0100 || 20-byte delegate` designator, then hashes the delegate's runtime code at the same EIP-1898 block hash. It writes no transaction and never suggests or installs a delegation. A missing finalized view, RPC inconsistency, unsupported block-hash query, malformed code, chain mismatch or stale observation is `UNKNOWN` and fails closed. A changed delegate address or code identity revokes the old grant generation; a per-block observation hash change alone does not. Observation freshness is capped at 30 seconds at authorization and M03 consumption boundaries.

The implementation uses one fixed Monad Testnet RPC endpoint and does not accept caller-supplied URLs, preventing SSRF via the API. The official Monad Testnet page was retrieved on 2026-10-03 and identifies testnet revision `v0.15.2` / `MONAD_NINE`; its rendered public-RPC table did not expose endpoint strings in the retrieved page. A read-only probe on 2026-10-03 returned chain ID `0x279f` (`10143`), finalized block `0x40c2a64`, and a successful EIP-1898 `eth_getCode` query with `requireCanonical: true` at that block hash. This is point-in-time reachability evidence only, not a sustained endpoint-health or reorg guarantee. No wallet address was queried. EIP-7702 state observation is evidence about code at a queried block, not proof of the wallet owner's intent, delegate safety or account control. Reorg uncertainty blocks authority.

## Capabilities, sessions, revocation and replay

The permission compiler validates exact schemas, action subset, chain/account/agent/policy binding, scope and quantitative ceilings, expiry, generation and delegation identity before producing deterministic canonical bytes and digest. It rejects unknown fields, wildcard scopes, self-expansion, arbitrary calls and non-allowlisted actions. A session can only narrow its parent grant and expire earlier; it cannot renew or resurrect a grant. The wallet owner can revoke an individual session with a fresh EIP-712 proof bound to the exact session hash, parent grant and revocation generation. Session revocation, its proof reference and nonce are persisted as append-only records; revocation is serialized with parent-grant changes. EIP-712 domains bind chain ID; application-level durable nonce ledgers separately bind the account, wallet, agent, grant, operation and domain. Database uniqueness prevents nonce reuse across concurrent calls and restarts.

Grant revocation and wallet unbinding lock the durable authority-state row and monotonically advance its generation. Individual session revocation appends a one-way session revocation record while holding the parent authority lock; revoking the parent grant or unbinding its wallet also invalidates all descendant sessions. The M03 authorization ref is revalidated at the M03 request and recovery boundary against the exact plan/action, current revocation generation, current wallet binding and recent delegation state. A revoked, stale, unknown or changed authority cannot be recovered or retried as an effect. M03 retains refusal and no-blind-retry semantics. The database transaction/locking contract for future live provider effects is still an explicit blocker; M04 does not add such an adapter.

## Evidence and read-only surfaces

Permission events are minimized: internal references and hashes, event type, timestamps, correlation IDs, result and reason codes only. Flight Recorder exposes a hash of each subject reference rather than the account/grant/plan identifier itself. An append-only sequence and predecessor hash chain detect tampering, deletion, reordering and broken heads. Flight Recorder shows the M04 event list and chain integrity beside M03 events. The permissions page is a wallet-signed read-only account-scoped status view, English by default with Brazilian Portuguese and Spanish translations. Evidence and client responses never contain signatures, keys or raw wallet payloads.

## Storage and operating controls

Migrations create the wallet bindings, agent identities, grants, authority states, sessions, session revocations, nonce ledger, authorization references, delegation observations, revocations and evidence chain. Database constraints and triggers make event records append-only, nonce values unique and generation/head changes monotonic. Wallet/account state changes require wallet-owner EIP-712 proofs or a trusted issuer signature; M03 execution requests separately retain their actor and execution-authorization proofs. Read requests require the wallet-owner proof described above; account IDs, display names and client-side labels alone grant no authority.

Before any future live provider effect adapter can be considered, a database-level kill-switch concurrency proof and documented disable-versus-in-flight semantics must exist. `MAINNET` remains hard-blocked and live Perpl writes remain disabled independent of configuration. Four previously accepted MODERATE Drizzle Kit/esbuild advisories remain carry-forward items for release review; they are not suppressed or reclassified.

## Validation scope

Automated tests use ephemeral, randomly generated keys inside test process memory only. They are not real users, wallets, chain observations or provider credentials. A `PASS` of these suites proves the tested code behavior only. Hosted quality/security services and a PostgreSQL-backed migration/concurrency run must be reported from their exact candidate SHA; pending/failed checks must remain labeled accordingly in the Evidence Bundle and PR.
